# 对话分享渲染与附件预览：任务总览

日期：2026-10-20。状态：方案已确认，执行任务尚未开始。本文档集是后续实施大纲，不代表功能已经实现或通过验收。

## 1. 目标与范围

修复主会话、应用内会话预览、公开分享和下载 HTML 之间的渲染边界，使只读页面不再依赖主应用运行时；公开分享增加 HTML、图片、视频、音频预览。继续使用 WebClient 构建产物显式同步到 Tunnel、随 Relay 发布的现有流程。

这里的“同步”指显示资源的构建和发布同步，不是会话内容持续同步、双向同步或分享创建后的自动更新。分享内容和附件仍在创建时冻结。

最终合同、数据字段、HTML 隔离及兼容规则统一以 [01：最终技术方案](01-solution.md) 为准；子任务引用该方案，不维护另一份协议。

## 2. 不可违背的实施约束

1. 职责划分清晰：Platform 发现资源，Desktop 冻结上传，Tunnel 校验、存储和授权读取，WebClient 展示。
2. 直接修改现有入口；新函数或文件必须解决当前真实问题，不能只为“架构完整”增加层级。
3. 复用 `ConversationStage`、`TimelineInteractionContext`、`ShareAttachmentViewer`、现有文件存储及资源发布脚本。
4. 不建立新的 ConversationViewModel、通用渲染框架、插件注册中心、资源代理 RPC、同步服务、Repository、数据库资源模型或版本协商系统。
5. 替代旧实现时同任务删除失效回退与重复分支；不保留两条功能相同的处理链路。
6. 对已冻结且可由浏览器/前端直接读取的普通附件，新增预览主要修改类型判断和对应只读视图。不得每加一种格式就修改快照、冻结、鉴权、存储和时间线协议；需要转换或新增资源准入的格式单独评估。
7. 仅冻结已发布附件及本次分享内容明确引用的当前 Chat 媒体；不扫描目录、Workspace 或其他 Chat。
8. 下载 HTML 本次只修复渲染，不打包媒体，不承诺离线附件预览。
9. 保留既有额度配置、一次性分享会话、历史资产集和历史数据。不得引入前端额度默认值、放宽 Cookie 或清理旧资产。
10. 清理属于完成条件。保留用户原有修改，不改真实凭据，不提交、推送或部署，除非后续执行任务另有授权。

## 4. 执行顺序与提前验证

1. 记录四仓 Git 状态、相关配置和生成文件的原始状态，阅读各仓 `AGENTS.md` 和相关专题文档。
2. 先由 T4/T5 做最小真实浏览器验证：网络 iframe 文档、独立 CSP、一次性会话、一次性 Blob 交付、脚本执行。这是 HTML 方案的技术门槛，不能拖到所有 UI 完成之后；验证代码纳入最终实现或及时删除，不另建长期框架。
3. T1、T3、T4 可按明确边界推进；T2 接上 T1，T5 接上 T3/T4。多人工作时先约定文件所有权，尤其是前端快照解析、导出根组件和构建脚本。
4. T6 用同一组脱敏样例串联创建、打开、预览、下载、撤销、过期及一次性访问，再执行渲染产物同步和历史资产检查。
5. 部署顺序：兼容的新 Tunnel 与匹配渲染资产先上线，再发布配套 Platform/Desktop 和主 WebClient。部署另需当次授权，本轮只落文档。

若最小浏览器验证失败，应就该实现点修正并更新 01；不得自行退回 `allow-same-origin`、`srcdoc`、明文 URL token 或通用资源代理。

## 5. 统一完成标准

- [ ] T1–T5 各自验收通过，原有主会话行为保持。
- [ ] 四个渲染入口均覆盖成功图片生成、附件、引用、Planning、公式、图表和操作失败。
- [ ] 公开分享四类附件可预览，浏览器不支持的编码有下载回退。
- [ ] 缺失、超额、无权限、变化和超时均逐项说明，正文仍可分享。
- [ ] 一次性分享的同浏览器续读、跨浏览器拒绝以及媒体跳播语义成立。
- [ ] HTML 脚本与媒体在隔离文档运行，不能获得分享 Cookie、宿主运行时或任意资源读取桥。
- [ ] 旧快照可读；旧下载 HTML 所引用的历史资产仍可访问。
- [ ] 删除被替代的逻辑；未加入禁用的抽象或无需求能力。
- [ ] 完成 T6 清理审计；所有未运行检查及外部限制明确记录，不能写成通过。
