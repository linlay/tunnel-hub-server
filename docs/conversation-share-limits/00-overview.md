# 对话分享与导出额度：重写方案

2026-10-19。状态：必要性报告所列代码问题已修复并复验，清理审计完成；外部验证限制见 05。本文替代上一版实施细则，以职责清晰、直接修改、删除重复处理为验收标准。

## 目标

业务额度仅在 Tunnel 和 Platform 配置，默认各 50 MiB。Desktop、WebClient 不保存业务默认值，不增加配置中心或兼容旧额度分支。保持 Snapshot V1、历史链接、附件省略、鉴权与既有发布流程。

| 责任 | 唯一位置 | 客户端使用方式 |
| --- | --- | --- |
| 新分享正文/附件准入 | Tunnel 上传解析入口 | Desktop 每次创建读取 `/api/desktop/shares/limits`，用于附件选择及最终快照组装 |
| 独立导出准入 | Platform 快照生成出口 | 响应携带 `X-Conversation-Export-Max-Bytes`，客户端有界读取 |
| 数据完整性 | 原有解析、存储和资源模块 | 保留版本、时间、长度、哈希及鉴权，不重复定义业务额度 |
| HTML 输出 | 现有模板组装 | 删除 HTML 业务上限，保留安全转义和运行时分配错误处理 |

Tunnel `.env` 使用 `CONVERSATION_SHARE_MAX_SNAPSHOT_MIB`、`CONVERSATION_SHARE_MAX_RESOURCES_MIB`；Platform `configs/runtime.yml` 使用 `conversation-export.max-snapshot-mib`。只接受可安全换算的正整数，启动读取、重启生效。总上传体积由正文、附件加 1 MiB multipart 开销计算。

3. Platform：保持原快照构建签名，只构建、序列化一次。HTTP/工具在真实导出出口检查配置额度，普通投影不接触额度；工具不重复构建，并保持空 Markdown 原语义。
4. Desktop：复用原有读取器与冻结流程，分别使用 Platform 读取额度、Tunnel 分享额度和附件预算。附件回退按元数据长度计算，正文只序列化一次；删除 HTML 及保存前复查。
