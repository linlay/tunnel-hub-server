# Desktop：额度对接与编排

每次创建先通过现有 Tunnel client 查询额度，再传入 Worker。失败立即结束；不缓存，不回退本地额度。历史列表/打开/撤销不查询新建额度。

- 沿用现有 HTTP reader。Snapshot 从 Platform 头读取额度，先确认声明长度可接受，再按该长度有界写入并验证完整性；删除循环中重复的业务额度判断。
- 附件按 Tunnel 剩余预算读取；保留 MIME、长度、哈希、超时和权限的原有省略语义。
- 正文序列化一次，附件声明独立序列化并计算元数据预算。超额只从尾部删除附件声明及文件，不反复序列化整份正文。
- HTML 沿用原有安全转义/长度计算，删除固定 HTML 政策、转义遍历中的限额判断及落盘前检查；分配失败走明确提示。

验证：main 类型/发布 bundle 构建、renderer 类型、架构、双契约、i18n 均通过；5 个既有相关测试文件共 31 项通过，包含独立发布 Worker。22 MiB 本机快照读取、HTML 输出及降低分享额度拒绝通过。
